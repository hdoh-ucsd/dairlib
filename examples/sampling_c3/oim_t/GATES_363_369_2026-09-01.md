## One-to-one controller math

For measured tip `p_m`, bounded command `p_c`, configured reposition speed
`v_r`, and unchanged planning interval `dt`, each xArm6 segment now uses

```text
Delta t = max(dt, ||p_c - p_m|| / v_r),
p_d(t_0) = p_m,
p_d(t_0 + Delta t) = p_c.
```

The velocity-servo bridge uses the same segment time,

```text
qdot_ff = clip((q_star - q_m) / Delta t, -qdot_limit, qdot_limit),
```

instead of dividing every posture change by 50 ms. No velocity limit changed.
The Cartesian command-acceleration bound is derived from the existing values,
`a_max = Kp_task .* approach_command_step = 200 * 0.05 = 10 m/s^2`, matching
the Panda OSC bound without adding a YAML key or retuning a value.

The reposition QP retains the collision-certified six-joint target, but its
quadratic objective is the already-configured regularizer

```text
J_posture = 0.01 ||q - q_star||^2,
```

under the unit-weight Cartesian task. The selected C3 input is passed without
scaling or sign changes,

```text
lambda_d,k = u_star,k,
```

through `end_effector_force_target`; acquisition/release knots command zero.
This is the same DAIRLab path used by Panda (`u_sol` to desired external
end-effector force). Panda's configured input-smoothing weight is zero, so no
new smoothing cost was added.

Target ownership uses the reference relative hysteresis:

```text
retain previous iff
  previous is available and not invalidated, and
  C_previous < C_best + eta C_previous.
```

The existing `successor_cost_hysteresis_fraction` supplies `eta`.
